# FAQ 常见问题

1. 渲染引擎为什么适合面向对象？

   向量、材质、相机、渲染器都是「数据 + 行为」的对象：用封装管住状态，用 RAII 管住资源，用多态扩展行为。

2. 封装为什么重要（不变量）？

   public 放接口、private 藏实现——外部改不了成员才能保证不变量（如「法线永远是单位向量」）。

3. RAII 是什么？为什么用 std::vector / unique_ptr 代替 new / delete？

   资源获取即初始化：内存、文件、锁的申请和释放绑在对象的构造/析构上，离开作用域必然执行，泄漏和双重释放基本绝迹。

4. 为什么声明放 .h、实现放 .cpp？

   编译更快、依赖更清晰；头文件用 #pragma once 防重复包含。

5. 基类析构为什么必须 virtual？

   Renderer* p = new Rasterizer; delete p; 只调基类析构 → 子类资源泄漏。

6. 什么是对象切片？

   Renderer r = rasterizer; 值拷贝到基类对象，丢掉子类部分，多态失效。

7. 什么是名字隐藏？

   子类定义 foo(int) 会把基类所有 foo 重载藏起来，需要 using Base::foo;

8. 成员按什么顺序初始化？

   按声明顺序（不是构造函数初始化列表顺序），两者保持一致可避免隐患。

9. 构造/析构里能调虚函数吗？

   别调：此时子类还没构造完/已析构，调的是基类版本。

10. 值语义和引用语义分别用在什么对象上？

    向量、矩阵、颜色用值语义（小而自包含）；纹理、网格等大资源用指针/引用共享，配合 shared_ptr 管理生命周期。
