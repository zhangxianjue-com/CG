# FAQ 常见问题

1. 编译器是什么？

   ::: details 查看答案
   把**人类可读的源码翻译成机器可执行的程序**的工具。你写的是 C++（给人看），CPU 只认二进制机器码（给机器执行），编译器就是中间的翻译官。

   类比：把中文菜谱翻译成厨师看得懂的工序单。翻译的输入是 .cpp/.h 源文件，输出是 .exe（Windows）或 ELF 可执行文件（Linux）。
   :::

2. 编译四步各做了什么？

   ::: details 查看答案
   1. **预处理**：展开 `#include`（把头文件内容粘贴进来）、处理 `#define` 宏、按 `#if` 条件裁剪代码——纯文本操作，输出仍是源码
   2. **编译**：源码翻译成**汇编代码**（.asm），做语法检查——你看到的 C 开头语法错误在这一步报出
   3. **汇编**：汇编翻译成**目标文件**（.obj）——机器码，但里面引用的函数地址还没填
   4. **链接**：把多个 .obj 和库（.lib）拼成一个 .exe，把函数调用地址接上——LNK 开头的「无法解析的外部符号」错误在这一步报出
   :::

3. 编译器、编辑器、IDE 是什么关系？

   ::: details 查看答案
   编辑器负责「写」（VS Code、Notepad）；编译器负责「翻译」（cl.exe、g++）；IDE 是打包好的全家桶：编辑器 + 编译器 + 调试器 + 工程管理（Visual Studio 就是 IDE）。

   所以 VS Code 配 MSVC 是「编辑器 + 编译器」组合，Visual Studio 是自带编译器的 IDE。
   :::

4. MSVC、GCC、Clang 怎么选？

   ::: details 查看答案
   - **MSVC**：微软编译器（cl.exe），Windows + VS 标配，本机就在用
   - **GCC**：Linux 默认；Windows 上经 MinGW 使用
   - **Clang**：LLVM 项目，跨平台、报错信息友好，工具链生态强

   同一份标准 C++ 代码三家都能编译；跟着平台走即可——Windows 开发用 MSVC，Linux 用 GCC，macOS 用 Clang。
   :::

5. 常见编译报错怎么看？

   ::: details 查看答案
   - **C 开头**（编译期）：语法错误、类型错误——看报错行号改代码
   - **LNK 开头**（链接期）：调用了声明过但没实现的函数、没链接库——检查实现文件 / target_link_libraries
   - **warning 警告**：不阻断生成，但值得修（如未使用变量、类型转换）

   报错信息从第一条开始看，后面的常常是第一条引起的连锁反应。
   :::

6. Debug 和 Release 是编译器的事吗？

   ::: details 查看答案
   是编译**选项**的差异：同一个编译器用不同参数产出不同版本——
   - Debug：`/Od`（不优化）+ 调试信息（/Zi）+ 断言开启，编译快、运行慢，用来调试
   - Release：`/O2`（优化）+ 去掉调试信息，运行快，发布用

   VS 工具栏切换配置，或 `cmake --build ... --config Release`。
   :::
