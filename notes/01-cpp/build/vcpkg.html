FAQ 常见问题 ​

  1. vcpkg 是什么？

    查看答案

    微软开源的 C++ 包管理器：负责第三方库的下载、编译、版本与依赖管理，类似 npm 之于 JS、pip 之于 Python。

    vcpkg install glm:x64-windows 三件事：下载源码 → 编译成预编译二进制包 → 装到 vcpkg 目录。装库 A 时它依赖的 B、C 自动带上。与 FetchContent 的本质区别：vcpkg 是「预编译 + 全局安装」，FetchContent 是「源码内联进你的构建」。

  2. 和 FetchContent 怎么选？

    查看答案
    • FetchContent：小库、纯头文件库（GLM），源码即用，克隆仓库一条 cmake 命令全自动——本项目用法
    • vcpkg：大库（boost 级）或多库、要统一管理版本、CI 里共享缓存——编译一次全局复用，快得多

    两者可以混用：工程主体依赖走 vcpkg，个别源码级依赖走 FetchContent。

  3. 三元组（triplet）是什么？

    查看答案

    指定目标平台 + 架构 + 库形态的组合名，跟在包名冒号后：glm:x64-windows（64 位 Windows 动态库）、glm:x86-windows-static（32 位静态库）、glm:x64-linux。

    装同一个库的不同三元组互不干扰，按需安装。

  4. 必须和 CMake 配合吗？

    查看答案

    不必须，但最省事的就是配合 CMake：

    1. 配 CMake：配置时加 -DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake，之后 find_package / target_link_libraries 自动找到装好的库
    2. 配 VS（MSBuild）：vcpkg integrate install 让 .sln 项目直接引用，不用手配包含目录
    3. 单独用：装好后手动配包含目录（丢掉自动化意义，不推荐）

  5. 版本怎么管？

    查看答案

    经典模式装的是 registry 当前最新，不锁版本；要可复现用 manifest 模式：项目根放 vcpkg.json 声明依赖与版本，CMake 配置时自动安装并锁定。

    json
    {
  "dependencies": [
    { "name": "glm", "version>=": "1.0.1" }
  ]
}

  6. 本项目为什么不用 vcpkg？

    查看答案

    依赖少且都是头文件库（GLM）、FTXUI 只需一个版本：FetchContent 已够用，多装一个包管理器反而增加维护面。等出现「大库 + 多版本」需求再引入。
