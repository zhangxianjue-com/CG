CMake 是跨平台构建工具：一份 CMakeLists.txt 描述工程，生成各平台的构建文件，再调用底层工具编译。

Markmap 知识体系 ​

cmake
├── 官网地址：https://cmake.org/download/
├── 工程文件
│   ├── CMakeLists.txt 工程描述文件
│   │   ├── cmake_minimum_required(VERSION 3.24)  # 最低 CMake 版本
│   │   ├── project(ProjectName LANGUAGES CXX)    # 工程名 + C++ 语言
│   │   ├── add_executable(ProjectName main.cpp)  # 生成 ProjectName.exe（main.cpp 入口文件）
│   └── CMakePresets.json 预设文件
├── 构建指令
│   ├── cmake -B build          # 配置：生成 build/ 里的构建配置文件
│   └── cmake --build build     # 构建：将「代码内容」编译成 .exe 可执行文件
├── 构建产物
└── END

FAQ 常见问题 ​

  1. 如何安装 CMake、并检验是否安装成功？

    查看答案

    三种安装方式（任选其一）：

    1. VS 组件：Visual Studio Installer →「修改」→ 勾选「适用于 Windows 的 C++ CMake 工具」——随 VS 安装，无需单独配置
    2. winget：winget install Kitware.CMake——一条命令装好并自动加入 PATH
    3. 官网：https://cmake.org/download/ → Windows x64 安装包，安装时勾选 Add CMake to PATH

    检验：终端执行

    bash
    cmake --version

    输出 cmake version x.y.z 即成功；若提示「不是内部或外部命令」，说明 PATH 没生效，重启终端再试。

  2. 如何 Cmake 构建一个最小的 C++ 程序？

    查看答案

    一个目录放两个文件：

    hello/
├── CMakeLists.txt
└── main.cpp

    main.cpp：

    cpp
    #include <iostream>
int main() {
  std::cout << "Hello CMake";
  std::cin.get();  // 等按一下回车再退出
  return 0;
}

    CMakeLists.txt（最小三行）：

    cmake
    cmake_minimum_required(VERSION 3.24)   # 最低 CMake 版本
project(hello LANGUAGES CXX)           # 工程名 + C++ 语言
add_executable(hello main.cpp)         # 生成 hello.exe

    然后两步构建：

    bash
    cmake -B build          # 配置：生成 build/ 里的构建文件
cmake --build build     # 构建：编译出 hello.exe

    运行 build\Debug\hello.exe，打印 "Hello CMake"。

  3. Cmake 如何在构建时自动拉取 C++ 第三方库（如 glm）？

    查看答案

    用 CMake 自带的 FetchContent，自动拉取发生在配置阶段（cmake -B build 时），不是编译阶段。CMakeLists.txt 里三步：

    cmake
    include(FetchContent)                           # 引入模块
FetchContent_Declare(glm                        # 声明：仓库 + 锁定版本
  GIT_REPOSITORY https://github.com/g-truc/glm
  GIT_TAG 1.0.3)
FetchContent_MakeAvailable(glm)                 # 下载并纳入构建
target_link_libraries(glm-cpp PRIVATE glm::glm) # 链接

    配置时 git clone 源码到 build 缓存（之后离线可重复构建），和你的工程一起编译——纯头文件库（glm）零编译成本，下载完直接 include 即用。

  4. 改了 CMakeLists.txt 需要重新配置吗？

    查看答案

    需要重新配置，但通常不用手动做：cmake --build build 构建前会检测 CMakeLists.txt 的时间戳，变了就自动先重新配置再编译；VS 打开文件夹时保存 CMakeLists.txt 也会立即自动重新配置。

    日常流程：

    • 只改代码 → 直接 cmake --build build（增量编译，只编改过的文件）
    • 改 CMakeLists.txt / CMakePresets.json → 直接 build 也行（自动补配置）；显式 cmake -B build 更保险、日志看得清
    • 换工具链 / 配置缓存异常 → 删 build 目录重新 cmake -B build

    一句话：配置一次、构建多次；改了 CMakeLists 忘了重跑配置没关系，build 会替你补上。
